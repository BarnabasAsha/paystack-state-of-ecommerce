## What this is

A single-page marketing/report site for Paystack's "State of Ecommerce" report — a long-form scrollytelling page (`Hero` → `CommerceTimeline` → `TimelineEnd`) built with Next.js App Router. There is currently only one route (`src/app/page.tsx`); this is not a multi-page app.

## Commands

Package manager is **pnpm** (see `packageManager` in package.json).

```bash
pnpm dev      # start dev server (Turbopack via Next 16)
pnpm build    # production build
pnpm start    # run production build
pnpm lint     # eslint (flat config: eslint-config-next core-web-vitals + typescript)
```

There is no test runner configured in this repo.

## Next.js 16 — read before writing route code

This project is pinned to Next.js 16, which has breaking changes vs. older Next.js knowledge baked into training data. **Before touching anything under `src/app/` (routing, layouts, metadata, params/searchParams, data fetching), read the relevant doc in `node_modules/next/dist/docs/`** rather than relying on prior Next.js conventions. Notable difference already in use here:

- `layout.tsx` / `page.tsx` type their props with the generated `LayoutProps<'/route'>` / `PageProps<'/route'>` helpers (global, no import needed) instead of hand-written prop types — see `src/app/layout.tsx`.

The `AGENTS.md` "breaking changes" banner is regenerated by `next dev` on every run (`node_modules/next/dist/server/lib/generate-agent-files.js`) — don't try to remove it permanently; committing it is expected and keeps the tree clean.

## Architecture

**Component-per-folder pattern.** Every UI piece lives in `src/components/<name>/` with co-located CSS Modules, and often co-located data/types/hooks:

```
src/components/commerce-timeline/
  commerce-timeline.tsx       # "use client" component
  commerce-timeline.module.css
  data.ts                     # static content (commerceTimelineData)
  types.ts                    # TimelinePhase / TimelineEvent shapes
```

`hero-circle-grid/` follows the same idea but splits pure logic into standalone modules alongside the component: `africa-shape.ts` (cell-map data), `grid-placement.ts` (pure placement/breakpoint math), `use-breakpoint.tsx` / `use-grid-dimensions.tsx` (hooks). When adding non-trivial logic to a component, prefer extracting it into a sibling module like this rather than growing the `.tsx` file.

**Styling:** CSS Modules only (no CSS-in-JS, no Tailwind). Class lookups use bracket syntax with hyphenated BEM-ish names, e.g. `styles["commerce-timeline_container_lcol_wrapper_title"]`, because the names contain hyphens/underscores that aren't valid JS identifiers. Global tokens (brand colors, font vars, breakpoints) live in `src/styles/globals.css` as CSS custom properties (`--commerce-orange`, `--breakpoint-tablet`, etc.) — reuse these rather than hardcoding values. Component-specific runtime values (grid columns, computed sizes, per-phase growth factors) are passed down as inline CSS custom properties via `style={{ "--foo": value } as React.CSSProperties}` and consumed in the module CSS.

**Client vs. server:** Components that measure the DOM, use `ResizeObserver`, or read window size are `"use client"` (e.g. `commerce-timeline.tsx`, `hero-circle-grid.tsx`). Keep new components server components by default unless they need browser APIs, state, or effects.

**Data-driven content:** Long-form content (timeline phases/events) is modeled as typed data (`types.ts`) and populated in a plain data file (`data.ts`), then mapped over in the component — not hardcoded JSX per item. Follow this pattern when adding more timeline phases/events rather than writing repeated markup.

**Fonts:** Custom fonts (Boing, Graphik) are self-hosted under `src/assets/fonts/` and declared via `@font-face` in `fonts.css`, imported from `globals.css` — not `next/font`.

**Path alias:** `@/*` maps to `src/*` (see `tsconfig.json`).
